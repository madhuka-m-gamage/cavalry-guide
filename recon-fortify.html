Establish the environment once, audit read-only, then pin down risky behaviour with tests before anything changes.

Pre-flight

Run by Recon at the start of a program; Charge re-runs it when the tracker says Preflight: stale. Results go into the tracker header.

Recon

Invoke with /cavalry:recon. Never changes code or deploys.

  1. Runs pre-flight, then asks only what has more than one reasonable answer: branch, uncommitted work, scope, backend, findings location, parallel or sequential.
  2. In parallel mode: one agent per module plus one that owns the authorization matrix, sharing ids-registry.md, each returning at most 20 lines.
  3. Removes duplicates by root cause and spot-verifies every critical finding.
  4. Checks your quality gates actually cover the code; marks every finding Verified: read | ran | unverified.
  5. Asks decisions in batches of four with a recommendation, and builds the queue with Deploy values.

Fortify

Invoke with /cavalry:fortify. Writes tests, test infrastructure and CI, never fixes.

  1. Detects the stack and test runner; confirms existing tests pass first.
  2. Creates one shared backend fake that re-exports the real SDK's sentinel helpers.
  3. Writes characterization tests named BUG <id> … flips in <Qn> for money, auth and flagged paths.
  4. Corrects Recon findings that don't reproduce, on the record.
  5. Done only when CI runs the full gate on both branches and the checks are required.
