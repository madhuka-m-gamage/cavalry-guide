Phases 4–5

Regroup and Breach

An optional restructure that proves it changed nothing, then a rollout where every production step waits for your go.

Regroup (optional)

  1. Write a manifest, one old -> new per line, placing every file the remaining queue will touch.
  2. Dry run shows every move and import rewrite; nothing changes until you confirm.
  3. --apply uses git mv and rewrites imports; then the full gate; then cavalry-verify-pure-move.
  4. One PR per group; the next group starts after it merges.

Breach

  1. Reads, read-only, what is actually live. It never assumes main equals production.
  2. Builds the runbook from Deploy values in order, with the promotion (merge commit) in its place.
  3. Each step has a pre-check, a verification and its own rollback.
  4. You approve the runbook, then say go before every production step.
  5. For rules backends: an emulator test, then a byte-identical check of the live ruleset.
